### 先判断问题属于哪一类

| 类型 | 怎么判断 | 用哪种正文 |
|---|---|---|
| 健康检查 | 要巡检、体检(此刻或某段时间),或参数体检 | 巡检四段(gaussdb-health、gaussdb-config) |
| WDR 解读 | 要某段时间、两个快照之间的 WDR 分析 | 由 gaussdb-wdr 的脚本渲染 |
| 故障排查 | 描述一个现象或告警:交易超时、库变慢、锁等待多、连接满、表膨胀、内存高、某个告警…… | 故障排查四段(见下) |
| SQL 优化 | 要优化某条 SQL,或问某条 SQL 为什么慢 | SQL 优化四段(gaussdb-sqltune;存储过程用 gaussdb-proctune) |
| 只看执行计划 | 只要看计划、不要优化 | 执行计划解读(gaussdb-explain) |
| 榜单 | Top SQL、慢 SQL 列表 | 榜单(gaussdb-topsql、gaussdb-slowsql) |
| 知识问答 | 问规范、参数、错误码、视图字段、功能、做法,不查实例 | 知识问答(见下) |
| SQL 审查 | 审查 SQL / DDL 是否合规 | 照下文「SQL 审查输出」 |

重叠时:点名要健康检查的按健康检查;点名优化某条 SQL 的按 SQL 优化;既要查实例又要结合知识的按故障排查。
进入某个技能后,以那个技能 SKILL.md 里「## 回答模板」一节为准。
