# 官方文档集(标准知识库)

GaussDB 官方产品文档(CHM)由脚本按目录切分成「高斯产品文档」条目,放在 `<kb>/docsets/<代号>/`,
与客户自己的知识分开存放、分开检索(官方文档单独一个候选池,不会把贵行规范与案例挤出候选)。

## 目录

| 路径 | 内容 |
|---|---|
| `manifest.json` | 代号、文档名、产品系列与版本、条目数、索引状态 |
| `catalog.json` | 每条的 ID、标题、摘要、专题、目录路径(L0 / L1 / 大盘只读它) |
| `items/PD-<代号>-NNNNN.md` | L2 条目 |
| `pages/<页>.md` | L3 原页(整页 markdown) |
| `plan/` | 构建配方:`plan.yaml` 元数据与范围、`topic-map.yaml` 专题映射与覆盖、`ids.yaml` 编号表、`summaries.yaml` 精修摘要 |
| `index.sqlite` | 这一套自己的检索索引 |

## 切分

- 一页一条(只有目录、没有正文的导航页不成条);
- GUC 参数页一参一条:参数说明 / 参数类型 / 参数单位 / 取值范围 / 默认值 / 设置方式 / 设置建议 / 设置不当的风险与影响;
- 错误码页按页成条,检索块按错误码一码一块(只建关键词);`kb.py show <ID> --grep GAUSS-xxxxx` 只给那一码;
- 页内小标题(现象描述、可能原因、处理步骤…)成为小节;摘要 ≤ 200 字。

## 专题

按目录(锁管理 → 锁与阻塞,自动清理 → 膨胀与回收,SQL调优指南 → 慢 SQL…)、系统表 / 视图按名字
(PG_LOCKS → 锁,PG_STAT_ACTIVITY → 连接)、其余按同义词推断;`plan --override "<目录>=<专题>,…"` 人工覆盖优先。
标准知识库只用默认专题(各客户的自定义专题不进官方文档集)。

## 要用户确认的

1. 范围(全部,或去掉哪几章);2. 产品系列、适用版本范围、部署形态;3. 文档版本、内核版本、发布日期;4. 文档集代号;
5. 专题映射表与样例;6. 要不要精修重点页摘要。都由用户定,你只提议。

## 摘要精修

`kb.py docset summaries <代号> --next 10` 给一批重点页(故障处理、SQL 调优、开发设计建议、开发最佳实践、FAQ、巡检、开发设计规范)的原文;
写 `{"<ID>": "<摘要>"}` 的 JSON,`--apply` 交回。要求:≤200 字,结论在前(这页能回答什么问题、关键判断与做法),
只写原页里有的;摘要里出现的英文标识(参数名、视图名、等待事件名)与数字必须原样出自原页,否则整条退回。
精修过的摘要在 `show` 里标「摘要由模型依据原页撰写」。

## 适用性

条目的产品系列与版本取自配方(如 GaussDB 集中式 / 505.2),诊断时与本实例画像比对;不符的标「不适用本环境」。
测试环境可在 `kb.yaml` 开 `test_switches: {docset_applicability_unknown: true}`(一律「适用性未知」),
`health` 每次提示,打标准知识库包时开着就拒绝。
