对比对象:交付分支标签 `diag-v1.5.0`(`8f6ad2b`)与 `diag-v1.5.1`(`3339d2f`);知识库导入包 `kbimport-v1.5.0`(`11caa2b`)与 `kbimport-v1.5.1`(`796cf04`)。
两个 v1.5.1 标签由测试仓库标签 `agent-v1.5.1` 经转化脚本生成。
本文全部内容可用 `git diff diag-v1.5.0 diag-v1.5.1` 复现;代码与 SQL 的完整原始差异见同目录 [`diag-v1.5.0..v1.5.1.diff`](diag-v1.5.0..v1.5.1.diff)
(不含自动生成的两份说明文档 `补充说明.md`、`whitelist/白名单脚本清单.md`,需要时用 `git diff diag-v1.5.0 diag-v1.5.1 -- 补充说明.md whitelist/` 查看)。

## 一、本版内容(技能包)

1. **M 兼容业务库上报错的诊断脚本改成 A / M 两种兼容模式都能执行的写法**(2026-11-20 现场反馈,v1.4.14 上 15 条报错):
   - `health.partitions`(分区体检):`max()` / `COALESCE()` 处理 `"char"` 列报 un support type → 先用 CASE 映射成文字再聚合;
   - `health.table_writes`(表写入计数):两个 name 类型取 COALESCE 推导成 any,报 `operator does not exist: any <> unknown`;外层引用的 `"table"`
     在 M 库是字符串常量(修好前一处后整列会变成字面值)→ 改成一层查询,名字列先转成文字,双引号只作最外层别名;
   - `health.stale_stats`(统计信息过期):`CAST(… AS float8)` M 库不认 → `* 1.0 /`;
   - `sqlreview.tables` / `sqlreview.indexes`(SQL 审查的表、索引清单):`TABLE` 是 M 库保留字,`AS table` 报语法错 → `AS "table"`;
     去掉 `ARRAY[]` 字面量,索引列顺序改用 `position`;
   - `procinfo.locate_search` / `proctune.locate_search`(过程模糊查找):M 库不支持 `ILIKE` → `lower(…) LIKE lower(…)`;
   - `health.unused_index`、`lockwait.pairs`、`explain.kernel_funcs`(v1.5.0 已改 `concat`)与 `procinfo.proc_def`、`proctune.proc_def`:
     名字类列进 `concat` / `COALESCE` 前显式 `::text`;
   - `procinfo.source_adm` / `proctune.source_adm`:M 库没有 ADM_SOURCE 视图,无对等写法,脚本不改,技能在 M 库上不再调用;
   - `memanalyze.wlm_*` 3 条:执行账号没有 WLM 函数权限(在 postgres 库执行,不是兼容问题),脚本不改,原因写成「执行账号没授权」。

   列名一律不变。白名单增量 `whitelist/scripts-delta-20261123.sql`:更新 13 条(只改脚本正文,不动执行库与参数),导入后仍是 132 条。
2. **识别业务库兼容模式**:登录探针多取 `datcompatibility` 与 `lower_case_table_names`,登录输出加「兼容模式」一行;M 库上存储过程源码不走
   ADM_SOURCE 兜底,EXPLAIN 前的语句检查同时按 A、M 两套词法切,取表名 / 补 schema 认反引号与表名大小写规则,SQL 审查按 MySQL 词法切分;
   SQL 调优、存储过程调优、SQL 审查的报告开头写兼容模式(只在 M 库出)。A 兼容库上的行为与 v1.5.0 相同。
3. **提示词小改**(模型按兼容模式写改写语句):`AGENTS.md` 加 3 行;`gaussdb-sqltune`、`gaussdb-proctune` 的 SKILL.md 各加半句、
   `gaussdb-sqlreview` 的 SKILL.md 改 1 句;新增 `references/gaussdb-m-compat-gotchas.md`(两个技能各一份,模型按需读)。
4. **部署自检**:加「业务库兼容模式」一项;新增 `--m-trial`,把 41 条在业务库执行的脚本用安全参数各试跑一次(只读),逐条列结果。

**未改动**:依赖(Python 包、系统程序)、配置文件格式、环境变量;除下表以外的技能、脚本定义与公共模块;`rootspec/`;各技能版本号。

**升级**:先把 `whitelist/scripts-delta-20261123.sql` 导入中间件(从 v1.5.0 以前的版本升级,先按 README 的顺序导到 20261119),再整包换技能包
(覆盖前备份 `common/config.yaml`、覆盖后还原);新开对话,运行一次部署自检,业务库是 M 兼容的加 `--m-trial`,把输出发回核对。
