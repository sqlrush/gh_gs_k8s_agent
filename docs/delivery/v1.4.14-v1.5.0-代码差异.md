# v1.4.14 → v1.5.0 代码差异

对比对象:交付分支标签 `diag-v1.4.14`(`51211ed`)与 `diag-v1.5.0`;知识库导入包 `kbimport-v1.4.14`(`ee1fb13`)与 `kbimport-v1.5.0`。
两个 v1.5.0 标签由测试仓库标签 `agent-v1.5.0`(提交 `ef0c077`)经转化脚本生成。
本文全部内容可用 `git diff diag-v1.4.14 diag-v1.5.0` 复现;代码与 SQL 的完整原始差异见同目录 [`diag-v1.4.14..v1.5.0.diff`](diag-v1.4.14..v1.5.0.diff)
(不含自动生成的两份说明文档 `补充说明.md`、`whitelist/白名单脚本清单.md`,需要时用 `git diff diag-v1.4.14 diag-v1.5.0 -- 补充说明.md whitelist/` 查看)。

## 一、本版内容(技能包)

1. **部署自检不再中途退出**(`gaussdb-login` 的 `scripts/selfcheck.py`):技能目录里漏放了技能包的 `scripts/` 时,自检读不到本地脚本定义,
   原来在「白名单核对」一项抛错、整份报告中断,后面的关键脚本试跑与数据库监控开关都没跑。现在「白名单」「白名单切库标注」两项标「无法比对」,
   写明原因与下一步(把 `scripts/` 整个放到技能目录下、与 `common/` 同一层),「业务库切换」与其余各项照常检查;
   另外每一项检查都有兜底,意外出错只把这一项记成 ✕,报告照常输出完。
2. **部署自检按白名单实际缺口列出要导的增量**:中间件里的白名单常常落后不止一个版本,原来只提示「按本版增量导入」。
   现在按缺了哪些脚本、哪些脚本的执行库对不上,推断从哪一份增量起、按顺序导完哪几份;推断不出时(只改了正文的增量,名字都在)
   提示把白名单导出交给我方核对。各份增量的内容放在新增的 `common/grmp/deltas.py`(从增量文件解析出的数据,随技能包安装,自检读得到)。
   中间件的清单接口只返回脚本名与参数、不返回正文,所以只改正文的增量没导时「白名单」一项照样是 ✓;现在 ✓ 时也点明「脚本正文是否为最新本项看不出,请确认已导到最新一份增量」(给出最新一份的文件名)。
3. **业务库脚本的拼接改用 `concat`**:M 兼容模式的业务库里 `||` 是逻辑或、不是字符串拼接,整条报
   「argument of OR must be type boolean, not type name」。在业务库执行的 4 条交付脚本改为 `concat(…)`:
   `lockwait.pairs`(锁堵塞成对明细)、`health.stale_stats`(统计信息过期)、`health.unused_index`(未使用的索引)、`explain.kernel_funcs`(内核函数探测)。
   `concat` 遇到空值时两种兼容模式的结果不同(A 兼容跳过空值,M 兼容返回空值),所以锁对象一列先判空再拼,两种模式都返回空串。
   列名、筛选、排序不变,技能代码不用改。白名单增量 `whitelist/scripts-delta-20261119.sql`:更新 4 条(只改脚本正文,不动执行库与参数),导入后仍是 132 条。
4. **引用核对认官方文档集的条目**(`gaussdb-kb` 的 `kb_cite.py`、`common/kb/docset.py`,两个包都有):回答里引用官方文档集条目
   (`PD-<代号>-<5 位>`,在知识库 `docsets/<代号>/items/` 下)时,原来一律判「疑似编造」;现在在用的文档集里有就判「存在」,
   只在整套退役的文档集里有就判「已退役」(提示以在用版本为准,不按编造处理)。
5. **安装说明**(`补充说明.md`):`scripts/` 与 `common/` 放同一层、设置 `GSDB_SKILLS_DIR` 列为必做项;耗时统计给出完整路径的写法;
   自检说明删掉已不适用的「多条语句」一项。
6. **白名单增量 `scripts-delta-20261116.sql` 注释更正**:其中 `vacuum.dead_tuples` 一条的变更说明注释原先误写成更早一次变更的说明,
   已更正;SQL 正文未改,已导入过的不用重导。

**未改动**:`AGENTS.md`;`skills/` 下除 `gaussdb-login/scripts/selfcheck.py`、`gaussdb-kb/scripts/kb_cite.py` 以外的全部技能
(技能说明 SKILL.md 与脚本)、各技能版本号;依赖(Python 包、系统程序)、配置文件格式、环境变量;
`common/` 下除 `VERSION`、`kb/docset.py` 与新增的 `grmp/deltas.py` 以外的全部文件;`scripts/registry/` 下除下表 4 条以外的全部脚本定义;`rootspec/`。

**升级**:先把 `whitelist/scripts-delta-20261119.sql` 导入中间件(从 v1.4.14 以前的版本升级,先按 README 的顺序导到 20261116),再换技能包;
换完新开对话,运行一次部署自检 —— 白名单还缺哪几份增量,自检会列出来。

## 四、后端(镜像)的变化(不在技能包里)

v1.5.0 的后端新增 **Fuyao 沙箱运行模式(预览)**:每个用户的诊断环境与知识库导入环境由 openFuyao 平台的微型虚拟机承载,
集群里新增状态服务与凭据代理服务;另有资源大盘(运维管理员看沙箱容量、组件、工号分布);发版台的白名单关卡同样按缺口列出要导的增量。
按需与固定池化两种运行模式照旧可用。镜像、部署与参数的变化见测试仓库 [gh_agent_k8s](https://github.com/sqlrush/gh_agent_k8s)
标签 `agent-v1.5.0` 的 `docs/版本说明.md`,部署步骤见本仓库 [docs/Fuyao沙箱部署手册.md](../Fuyao沙箱部署手册.md)。只装技能包的环境不受这部分影响。
