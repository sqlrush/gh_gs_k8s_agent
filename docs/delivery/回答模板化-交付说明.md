# 交付说明：回答模板化（2026-10-26）

本说明面向贵方的平台、中间件、前端三个团队：这一批改动之后，智能体的回答按问题类型固定版式、照顾开发人员与数据库工程师两种读者、
知识引用改为「上色 + 句后括号注明出处」。改动都在两个用户镜像（`gaussdb-agent-runtime`、`gaussdb-agent-kb-import`）里，网关不变。
实测效果见 `docs/reports/answer-template-comparison-20261026.html`。

|---|---|---|---|

## 1. 变更摘要

- **回答按问题类型固定版式**（详见《前端对接接口说明》3.7）：健康检查、故障排查、SQL 优化、知识问答、WDR 解读、Top SQL / 慢 SQL 榜单各有固定段落；
  共用开头（评估时段 → 总体状态 → 短结论）与结尾（「需要就 xxx 展开说明吗？」）。
- **两种读者**：正文每段先「应用视角」（给开发人员），再「数据库机制」（给数据库工程师），讲同一件事。
- **知识引用**：不再单列「客户知识库参照」，出自知识库的句子写进正文并上色，句后括号注明出处，例如「……（引用自贵行规范库 GS-CHG-003）」。
  本单位自己的规范、案例、手册、基线等蓝色 `#2f6fdb`；产品文档（官方文档集与导入的产品文档）青色 `#0f7c86`。
  知识库里没有时统一写「知识库中未找到相关内容，以下为通用知识，仅供参考」。
- **SQL 优化多了现状与趋势**：执行次数、平均 / 最大耗时，近 7 天按小时的变化，哪个时间点突然变慢、当时执行计划变没变（由脚本判定）；
  改写方案附 SQL 文本差异与改写前后的执行计划；优化后的耗时只有 cost 估算时写「需实测」。
- **WDR 报告**改为：负载画像 → 问题与元凶 → 解决方案 → 总结和结论 → 附录（版式由脚本渲染）。

## 2. 白名单增量（中间件团队）

`docs/delivery/scripts-delta-20261026.sql`：新增 3 条，全部只读，只访问系统视图；在 20261024 那份之后导入，导完共 126 条。

| 脚本 | 读取 | 用途 |
|---|---|---|
| `sqltune.stat_now` | dbe_perf.statement | 这条语句自统计清零以来的执行次数与平均 / 最大 / 最小耗时 |
| `sqltune.stat_trend` | snapshot.snap_summary_statement、snapshot.snapshot | 近 7 天每个 WDR 快照时刻的累计值，脚本相减得到按小时的趋势 |
| `sqltune.exec_history` | dbe_perf.statement_history | 每小时被记下的执行的平均 / 最大耗时与执行计划指纹（计划只在变化时给全文） |

趋势能看多远取决于贵方参数：WDR 快照保留期 `wdr_snapshot_retention_days`、逐次执行记录的保留期。

## 3. 升级（平台）

按《从源码构建到K8s运行-完整手册》构建两个用户镜像并改 `USER_IMAGE_TAG`；固定池化模式下还要换池子 StatefulSet 的镜像并逐个重建 Pod
（`updateStrategy: OnDelete`，一次一个）。用户在池子里的对话数据在 NAS 上，重建后接着用。

镜像里的 `AGENTS.md` 已经改好：原来的「引用规范（依据《文档名称》…）」「兜底策略」「诊断输出」「问答输出」换成了新模板，
「SQL 审查输出」「输出屏蔽规则」不变。贵方若用自己维护的 `AGENTS.md` 覆盖镜像里的那份，请照新镜像里标着
`<!-- ▼▼▼ 2026-10-26 回答模板化:替换原有写法 ▼▼▼ -->` 的 5 处替换，并整块照抄「## 回答模板」一节 —— 同一份提示词里两套格式，模型会随机挑一套。

## 4. 前端（前端团队）

回答里出自知识库的句子用 `<font color=#2f6fdb>…</font>`（本单位自己的知识）与 `<font color=#0f7c86>…</font>`（产品文档）两种标签上色，
HTML 白名单放行 `font` 的 `color` 属性即可。细节、示例与联调清单见《前端对接接口说明》v1.1 第 3.5、3.7、11 节。

## 5. 装后冒烟

| 问 | 看 |
|---|---|
| 对某个实例做一次健康检查 | 开头有总体状态与短结论；四段：现象 → 根因和证据链 → 解决方案（P0/P1/P2）→ 总结和结论；每段有「应用视角」「数据库机制」；结尾是「需要就 … 吗？」 |
| 对某条 sql_id 做调优并贴出执行计划 | 第一段有执行次数、平均 / 最大耗时与按小时的趋势（白名单增量未导入时写「暂不可得」） |
| 问一个参数的默认值和本单位的要求 | 第一行是「解答来源：…」；出自知识库的句子上色，产品文档是青色 |
