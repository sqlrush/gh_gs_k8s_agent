1.2 请求链路#

  • 对话：浏览器 → 贵方统一认证（认人，加工号头与信任凭据）→ 接入网关（核对信任凭据，找到或创建这个工号的用户环境）→ 用户环境里的 opencode。
  • 诊断取数：opencode 里的技能 → 同 Pod 的凭据代理（加上本人中间件令牌、SM2 签名、工号）→ 贵方中间件 → 被诊断的数据库。技能只能调用白名单里登记过的只读脚本。
  • 推理：opencode → 凭据代理（加上模型 Key）→ 贵方模型服务。
  • 报告与大盘：技能把报告写进本人 NAS 目录；前端经网关的 /reports/* 读取，大盘页面走 /dash/*。
  • 知识库：管理员在导入环境里导入规范、案例、官方文档，写进 NAS 的 kb/；所有用户环境只读这份知识库。

按需模式（默认）固定池化（可选）
怎么运行工号第一次登录时现建一个 Pod，闲置 30 分钟后收起部署时固定 N 个 Pod × 每个 K 个槽位，运行中不建、不删、不补

建议：先以按需模式上线、跑通全部验收；预计同时在线超过约 50 人、或要求秒级进入时，再按第 11 章切到固定池化。两种模式的 NAS 布局完全相同，可以来回切换，数据不迁移。

1.4 安全设计要点#

  • 凭据不进模型所在的容器：中间件令牌（按人）、SM2 签名私钥、模型 Key 只注入凭据代理容器，由它在转发时加上；模型执行命令读环境变量也读不到。 代理只往配置好的中间件与模型地址转发、只转发诊断接口，工号强制写成本人。
  • 只读白名单：技能只能按名字调用中间件里预先登记的脚本，126 条全部是只读查询，只访问系统视图与系统表，不读业务数据，不含 DML / DDL。
  • 网关不信任请求头：只认带着信任凭据的请求，信任凭据没配就拒绝启动；不带凭据的请求一律 403。
  • 网络策略白名单：用户容器只能出到中间件、模型服务与 DNS，访问不到网关、k8s API 与集群里的其他服务；网关只能访问 k8s API、用户容器与前端。
  • 最小权限：全部容器以非 root（uid 1000）运行；opencode 的工具权限写进配置真正执行：不能联网，只能用诊断技能，命令行只放行技能脚本与少数只读命令。
  • 固定池化的同 Pod 隔离：每个槽位独立的系统身份、进程空间与盘，凭据只在管家容器里，换人时容器重启清盘并经外部核验。

1.5 本版本要点#

  • 固定池化（可选部署形态）与凭据代理（凭据不进模型容器）。
  • 回答模板化：健康检查、故障排查、SQL 优化、知识问答、WDR 解读、Top SQL / 慢 SQL 各有固定版式，兼顾开发人员与数据库工程师两种读者； 出自知识库的句子上色并注明出处（贵方知识蓝色 #2f6fdb，产品文档青色 #0f7c86）。
  • 知识库：八类知识类型、L0–L3 渐进式披露、按环境画像判断适用性、官方文档集（CHM）导入。
  • 取数修正：用演练库造出 34 类典型故障、两轮逐项核对后修正的健康检查、锁回看、内存分析、Top SQL、SQL 调优等问题。
  • 中间件接口路径前缀改为部署配置：agent-config 的 GRMP_PATH_PREFIX，必填。
  • 诊断脚本白名单共 126 条（相对 v1.3.x 的 123 条：更新 12 条、新增 3 条）。

5. 构建镜像#

三种方式任选其一。

5.1 方式 A：本机架构构建（构建机与集群节点同架构）#

bash scripts/build-images.sh "$TAG"
docker images | grep "gaussdb-agent.*$TAG"     # 3 行:gateway、kb-import、runtime

核对镜像内容：

docker run --rm --entrypoint sh gaussdb-agent-runtime:$TAG -c 'opencode --version; ls -d /opt/agent/config/opencode/skills/gaussdb-* | wc -l; id'
# 期望:1.18.27 / 18 / uid=1000(agent)
docker run --rm --entrypoint sh gaussdb-agent-kb-import:$TAG -c 'ls /opt/agent/config/opencode/skills | grep gaussdb'
# 期望:gaussdb-kb、gaussdb-kb-import、gaussdb-kb-init 三行
docker run --rm gaussdb-agent-gateway:$TAG
# 期望:「配置错误,网关拒绝启动:缺 GATEWAY_NAMESPACE……」——网关缺配置时刻意拒绝启动,说明镜像是好的

对应《完整手册》3.1–3.3。

5.2 方式 B：两种架构一次构建并直接推进仓库（正式发布推荐）#

bash scripts/build-images.sh "$TAG" --registry <REG> --platform linux/amd64,linux/arm64 --push
docker buildx imagetools inspect <REG>/gaussdb-agent-runtime:$TAG     # 应看到 linux/amd64 与 linux/arm64 两行

Linux 构建机先装一次跨架构模拟：docker run --privileged --rm tonistiigi/binfmt --install all。用这种方式的跳过第 6 章。对应《完整手册》3.4。

5.3 方式 C：构建机不能上外网（离线包）#

在一台能上网的机器上构建两种架构并打离线包，带进内网：

bash scripts/build-images.sh "$TAG"                                      # 本机架构
bash scripts/build-images.sh "$TAG-amd64" --platform linux/amd64          # 另一种架构(本机是 arm64 时;反之换 arm64)
bash scripts/package-images.sh "$TAG"                                    # → dist/gaussdb-agent-v1.4.0-oc1.18.27/

离线包里是两种架构的镜像 tar.gz（各带 sha256）、k8s 清单与文档。内网里：

sha256sum -c *.sha256
gunzip -c gaussdb-agent-v1.4.0-oc1.18.27-<架构>.tar.gz | docker load

再按第 6 章推进内网仓库。

6. 推进镜像仓库#

REG=<镜像仓库前缀>            # 例如 registry.example.com/gaussdb-agent
docker login ${REG%%/*}
for img in runtime kb-import gateway; do
  docker tag gaussdb-agent-$img:$TAG $REG/gaussdb-agent-$img:$TAG
  docker push $REG/gaussdb-agent-$img:$TAG
done

每个 push 最后一行是 digest: sha256:...；denied 是没有推送权限。对应《完整手册》第 4 章。

SELECT count(*) FROM grmp.script_config WHERE scene = 'AGENT';                              -- 应为 126
SELECT count(*) FROM grmp.script_config
 WHERE script_name IN ('sqltune.stat_now', 'sqltune.stat_trend', 'sqltune.exec_history');    -- 应为 3

8.5 填 agent-config#

kubectl -n gaussdb-agent patch configmap agent-config --type merge -p '{"data":{
  "GRMP_API_HOST":"<中间件IP>","GRMP_API_PORT":"<中间件端口>","GRMP_PATH_PREFIX":"<中间件接口路径前缀>",
  "MODEL_BASE_URL":"<模型服务地址,以 /v1 结尾>","MODEL_ID":"<模型名>","MODEL_PROVIDER_NAME":"<显示名>"}}'
# 中间件要求签名时:
kubectl -n gaussdb-agent patch configmap agent-config --type merge -p '{"data":{"GRMP_APPKEY":"<中间件给的 Appkey>"}}'
  • GRMP_PATH_PREFIX 必填：技能调用中间件的两个接口是 <前缀>/common-operations 与 <前缀>/common-operations/invoke。以 / 开头、只写路径、末尾不带 /。 没填时登录数据库报「中间件接口路径前缀没有配置」；填错时中间件回 404。
  • 中间件地址不能写 localhost / 127.0.0.1（在容器里指容器自己）。
  • 签名口径、实例别名、模型看图、大盘站点前缀等其余配置项见附录 B。改了配置之后，之后创建 / 重启的用户容器才读到新值。

11. （可选）固定池化#

前提：按需模式已跑通第 10 章。

# ① 控制密钥(网关与各 Pod 的管家共用)
kubectl -n gaussdb-agent create secret generic sandbox-control --from-literal=KEY="$(openssl rand -hex 32)"
# ② 渲染并部署池子(默认 16 个 Pod × 8 个槽位)
python3 k8s/tools/render-pool.py --image $REG/gaussdb-agent-runtime:$TAG \
    --pool-size 16 --slots-per-pod 8 \
    --grmp-cidr $GRMP_IP/32 --grmp-port $GRMP_PORT --model-cidr $MODEL_CIDR --model-ports 443 > pool.yaml
kubectl apply -f pool.yaml
kubectl -n gaussdb-agent get pods -l app=gaussdb-agent,role=pool          # 每个 9/9 Running
# ③ 网关切到固定池化
kubectl -n gaussdb-agent patch configmap gateway-config --type merge -p '{"data":{"RUNTIME_MODE":"pool"}}'
kubectl -n gaussdb-agent rollout restart deploy/gateway
# ④ 从按需模式切过来时,把按需的用户容器缩到 0(容器退出前把数据写回 NAS)
kubectl -n gaussdb-agent scale deploy -l role=runtime --replicas=0
  • 规模：--pool-size 1–64、--slots-per-pod 1–16，单池最多 1024 个槽位；资源按第 2.2 节估。
  • 池化参数（闲置转保留 30 分钟、保留 7 天、每 Pod 留 1 个空槽位、满员时提前转保留闲置 10 分钟以上的人等）在 gateway-config，见附录 B。
  • 验证：curl -s -H "X-Admin-Token: $(cat ~/.agent-admin)" http://127.0.0.1:18089/admin/pool 看每个 Pod 与槽位的状态。
  • 切回按需：kubectl delete -f pool.yaml，RUNTIME_MODE 改回 ondemand，重启网关。数据都在 NAS，不丢。
  • 集群有 gVisor / Kata 时，渲染加 --runtime-class <名字> 整池启用沙箱运行时。

对应《完整手册》5.12（含渲染参数全表）。

12. 知识库初始化（知识库管理员）#

  1. 开通管理员：统一认证传的角色含 kb-admin（gateway-config 的 KB_ADMIN_ROLES 可改），或把工号登记进 ConfigMap agent-roles 的 kb-admins。 管理员访问 /kb-import 即进入自己的导入环境（模拟 SSO 下在命令末尾加参数 kb-admin）。
  2. 建索引：没有向量库要初始化，索引是 NAS 上的 kb/index/store.sqlite，导入流程会自动建；要手工建一次： kubectl -n gaussdb-agent exec deploy/kb-import-<管理员工号> -c opencode -- sh -c '. /data/env.sh && python3 /opt/agent/config/opencode/skills/gaussdb-kb-import/scripts/kb.py index'
  3. 导入贵方知识：在导入环境里把规范、案例（工单）、手册交给模型，按提示确认类型（八类：规范、案例、环境画像、指标基线、已知缺陷、处置手册、产品文档、Wiki）； 文件放进 NAS 的 kb/inbox/uploads/（或 kubectl cp 进导入容器的 /nas/kb/inbox/uploads/）。
  4. 登记环境画像（建议）：kb.py profile --system <系统代号> --alias <连接别名> --version-string "<登录输出里的版本串>"，补全后 kb.py add。 画像只写连接别名，不写 IP、主机名与口令。诊断时据此判断知识条目适不适用本实例。
  5. （可选）导入官方文档集：让模型按「官方文档集」流程导入 GaussDB 官方文档（CHM）：扫描 → 逐项确认范围、产品系列与版本 → 落盘 → 校验 → 建索引。
  6. 从旧版本升级的知识库：跑一次 kb.py migrate → 确认清单 → kb.py migrate --apply → kb.py validate && kb.py index。不迁移也能用，没类型的条目显示「未分类」。
  7. （可选）embedding：知识库配置里接上 embedding 端点后再跑一次 kb.py index 就补齐向量；不配时检索走词法 + 图，不影响使用。 embedding 服务在集群外时，网络策略要放行（固定池化渲染用 --egress <地址>/32:<端口>）。

完成标志：kb.py health 状态行正常、八类知识有计数；对话里问一条已导入的规范能引用到，并上色注明出处。对应《完整手册》5.7、5.11。
