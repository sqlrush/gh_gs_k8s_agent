## 一、通用提示词（开工前发一次）

```text
我要做一份 PPT《工行智能体方案介绍》，介绍我们交付给工行的数据库运维智能体。请你当我的搭档：我口述一页，你写一页。

【口径】
1. 产品统一叫「工行智能体」。全篇不出现「高斯」两个字；产品名不能带 GaussDB，但它用于 GaussDB 场景，说场景时可以写 GaussDB。
2. 运行时不写产品名，写「智能体服务」「诊断运行镜像」；只有需求页可以写「以开源 OpenCode 为基础」。
3. 客户一律写「工行」，不出现贵行、贵方、行方、本行、行内。
4. 只写已经做到的。没做到的在标题旁标「规划」「计划」或「对接」；编的数据标「示意数据」。
5. 数字必须从代码、交付物或实测记录里现查，查不到依据的不写。每页写完告诉我数字出处。

【内容取舍】
1. 图为主，六成以上的页面是架构图、原理图或流程图；字要少。
2. 不讲实现细节，不做成科普；讲价值、先进性和效果。
3. 每页一个标题、一行导语（关键的半句加粗），其余都是图。

【版式】
1. 16:9，画布 1600×900。每页自上而下：英文眉题、中文标题、一行导语、图示区（宽 1408）、页脚（PPT 标题与页码）。
2. 视觉沿用《基于K8s的GaussDB智能体方案介绍》那套：浅色底、圆角卡片、细线、线性图标、数字用专门的数字字体。
3. 颜色有含义，全篇一致：蓝 = 技能与证据、基础设施；紫 = 模型推理与规划中的内容；绿 = 知识与存储；橙红 = 拦截、风险与凭据；灰 = 外部系统。
4. 页面里的分组用虚线框加标签，节点之间的连线带短标签。

【做法】
1. 每页一个独立的源文件，生成 HTML 页面；脚本把各页拼成放映版，再逐页截图导出 PPT 和 PDF。
2. 章节分组和页序只在一处定义，目录、章节插页、页码都从这里取。
3. 每页写完先自己截图检查：文字不能折行后只挂一两个字，不能重叠，不能溢出卡片；改好了再在浏览器里给我看。
4. 生成时自动检查禁用词（高斯、客户称谓、把 GaussDB 当产品名的写法），出现就报错。
5. 正文全部写完后，再补封面、目录、章节插页和结束页。
6. 我会一页一页提修改意见，改完重新出图；每一轮的要求和你补充的内容都记进逐页记录。
```

自上而下四段：
1. 「一份原文」：一行的组成——原文、元数据（作用域、类型、出处、重要度、失效时间）、分词列（建倒排）、向量列（建向量索引）、关系（取代、提炼自、矛盾）。旁注：四种索引都从这一行派生，同一事务更新。

   - 向量——换了说法（HNSW）。例：上次那个跑得很慢的问题

   - B+ 树——过滤与排序（B-tree）。例：最近一周的排障记录
3. 「多路召回」五步：定作用域 → 准备查询 → 多路召回 → 融合排序 → 装入上下文。旁注：毫秒级，由引擎完成；模型只管提问和取用。
