# 发版台运维手册

> 带界面截图的版本：[发版台使用手册（在线查看）](https://sqlrush.github.io/gh_gs_k8s_agent/release-console/)，源文件 `docs/release-console/index.html`。

发版台是一个跑在**跳板机**上的独立程序（容器，不进 K8s），从 `agent-v1.4.4` 起随离线包发出。它把离线包里的版本部署到集群：
首次部署、升级、回滚都走同一套流程——发布前先**扫描全部资源**，齐全可用才能开跑；改动集群前给出**变更预览**由运维确认；
池子**按槽位在线替换**，正在用的人不受影响；最后用一个冒烟工号做一次**真实对话**验证。

手工做法（《从源码构建到K8s运行-完整手册》的部署与升级两章）仍然有效；两种做法不要在同一次发布里混着用。

## 1. 跳板机要求

| 项 | 要求 |
|---|---|
| 系统 | Linux x86_64 或 aarch64，装有 docker（能 `docker load`、`docker run`） |
| 集群访问 | 一份 kubeconfig，能访问目标命名空间（权限见 §1.1）；用**令牌或证书**方式认证（exec 认证插件在容器里没有，见 §9） |
| 网络 | 能到 K8s API、内网镜像仓库；用白名单「只读账号」方式时还要能到中间件库 |
| 磁盘 | 发布包目录放得下离线包（每个版本约 1 GB）；状态目录很小 |

### 1.1 kubeconfig 需要的权限（命名空间内）

ConfigMap 读 / 改，Secret 读 / 建，Deployment 改与删，StatefulSet 改，Pod 改与删，`pods/exec`、`pods/portforward`，
Job 建与删，NetworkPolicy 改。首次部署另需建命名空间（没有权限就请平台团队先建好命名空间与 PV）。
资源扫描的「Kubernetes」一项逐条核对这些权限，缺哪条写哪条。

## 2. 启动

1. 把离线包整个目录拷进**发布包目录**（例如 `/data/releases/`），**拷文件，不要用链接**：发版台在容器里只看得到这个目录，
   链到别处的文件看不到（界面上会标出来）。
   ```
   /data/releases/gaussdb-agent-v1.4.6-oc1.18.27/
     gaussdb-agent-v1.4.6-oc1.18.27-amd64.tar.gz(.sha256)   四个镜像
     gaussdb-agent-v1.4.6-oc1.18.27-k8s.tar.gz(.sha256)     清单与文档
     release.yaml(.sha256)                                  版本说明(镜像 digest、白名单全量、各版本变化)
     gaussdb-agent-release-v1.4.6-oc1.18.27-amd64.tar.gz    发版台自己
     release-console.sh                                     启动脚本
     rootspec-overlay.sh                                    换根规范模板(v1.4.5 起)
   ```
   换过根规范的（《部署上线方案》第 6.1 节），拷进来的是新包目录 `…-rootspec`，**原包目录不要同时放进来**（同一版本只能有一份）。
2. 运行启动脚本：
   ```bash
   /data/releases/gaussdb-agent-v1.4.6-oc1.18.27/release-console.sh
   ```
   脚本先核对发版台镜像的 sha256，再导入、启动，最后打印地址：`http://127.0.0.1:8090/`。
3. 发版台**只听跳板机本机**（不做登录）。在自己电脑上看：
   ```bash
   ssh -L 8090:127.0.0.1:8090 <跳板机>      # 然后浏览器打开 http://127.0.0.1:8090/
   ```

| 选项 | 默认 | 说明 |
|---|---|---|
| `--releases <目录>` | 本包目录的上一级 | 发布包目录（容器里只读） |
| `--state <目录>` | `~/gaussdb-release-state` | 发版台的状态：配置版本、发布记录、日志、渲染出的清单。**换发版台版本时用同一个** |
| `--kubeconfig <文件>` | `$KUBECONFIG` 或 `~/.kube/config` | 它引用的证书文件在别的目录也会一起挂进去 |
| `--port <端口>` | 8090 | |
| `--kubectl <文件>` | 镜像自带 v1.31 | 集群版本与 1.31 相差超过一个小版本时，资源扫描标黄；换成集群配套的 kubectl（静态二进制） |
| `--ca <文件>` | — | 内网镜像仓库的 CA 证书；资源配置里「CA 证书」填同一路径 |
| `--force` | — | 有发布正在执行也替换发版台（那一步会被中断，重启后停在原处等续跑） |

其他命令：`release-console.sh stop` 停；`release-console.sh logs` 看日志。发版台随跳板机重启自动起来，
正在执行的发布停在原处、标「被中断」，在界面上选续跑或回滚。

**换发版台版本**：在新版本的包目录里运行它的 `release-console.sh`，状态目录不变。已在运行同一版本时只打印地址；
有发布正在执行时不替换（等它停在确认关卡或做完）。

## 3. 资源配置

界面「资源配置」页。每次保存是一个**配置版本**，发布记录里写着用的是哪一版。密钥类只能写入、不能读回：
写进集群 Secret 的（模型 API Key、信任凭据等），发版台只留指纹；发版台自己要用的（镜像仓库口令、白名单只读账号口令）存在状态目录（权限 0600）。

| 分组 | 填什么 |
|---|---|
| 集群 | 命名空间（默认 `gaussdb-agent`）、kubeconfig 里的 context、节点架构（留空 = 自动识别） |
| 镜像仓库 | 方式：**推送**（发版台把包里的镜像推进内网仓库，默认）或**预载**（镜像已由平台载进每个节点）；仓库前缀（如 `registry.example/gaussdb-agent`）、账号、口令、CA 证书 / 不校验证书 / 明文 HTTP |
| 模型 | 地址（OpenAI 兼容）、模型 ID、API Key、是否支持图片输入 |
| 中间件 | 地址、端口、接口路径前缀、Appkey、签名方式、**实例别名**（`别名=IP/库名`，一行一个） |
| 网络策略 | 中间件、模型、K8s API、上游的网段与端口（只填集群外的；集群内的规则随版本） |
| 池子 | Pod 数 × 每 Pod 槽位数（只在首次部署时用；升级保留集群现有规模） |
| 统一认证 | 工号与角色的请求头名、信任凭据 |
| 白名单 | 核对方式：**导出文件**或**只读账号**（§6） |
| 冒烟 | 冒烟工号（要已开通中间件令牌）、做诊断用的实例别名 |

升级时，ConfigMap 按「**集群现值** + 新版本新增项的默认值 + 资源配置里填的」迁移，知识库管理员名单等现场改过的值原样保留；
网络策略里集群外的规则沿用集群现有的。

## 4. 资源扫描

「发布」页点「扫描资源」。**全部可用（黄色提示可以）且在 1 小时内**才能开始发布。

| 项 | 核对什么 | 不通过时 |
|---|---|---|
| 发布包目录 | 发现哪些包、目标包的 sha256 | 拷坏了重新拷；链接到目录外的文件换成真文件 |
| 内网镜像仓库 | 握手与认证 | 地址、账号口令、CA 证书 |
| Kubernetes | 命名空间、§1.1 的权限、节点架构、kubectl 与集群版本差 | 缺哪条权限请平台团队授；版本差大用 `--kubectl` |
| NAS | 在集群里以 uid 1000 写一个探针文件 | 请存储团队把 `users/` 的属主改为 1000 |
| 模型服务 | 在集群里发一句最短的对话（与智能体同一个接口、同一个模型 ID） | 认证失败 = API Key；400 / 404 = 模型 ID 或地址；402 = 余额；**503 / 429 = 服务方忙，稍后再扫** |
| 中间件 | 在集群里连中间件端口；接口路径前缀已设置 | 查网络策略的中间件网段；签名在冒烟时核对 |
| 白名单核对 | 导出文件已上传，或只读账号连得上、读到几条 | 见 §6 |
| 统一认证 | 信任凭据、冒烟工号的中间件令牌 | 请平台开通冒烟工号 |
| 集群余量 | 可分配内存 | 按槽位在线替换不额外占用 |

模型、中间件、NAS 三项借池子的管家容器在集群里测（密钥不出容器）；首次部署还没有池子时标黄，由冒烟验证核对。

## 5. 发布

「发布」页选目标版本（默认是比当前新的最新一个），先看**升级计划**：哪些步骤要做、哪些跳过、为什么，以及这个版本的提醒事项。
点「开始发布」后按地铁线一步步走，点任一步看明细与日志。

| 步骤 | 做什么 |
|---|---|
| 读包与校验 | 核 sha256、读 release.yaml、核对包里每个镜像的 digest |
| 生成升级计划 | 识别集群当前版本，累计中间各版本的变化（跳版本升级时一起做） |
| 镜像入库 | 推进内网仓库，已有的层跳过；推完回读 digest。集群里的镜像**按 digest 钉住** |
| 配置迁移 | 按 §3 迁移配置、渲染清单、生成与集群的差异 |
| **变更预览 · 确认** | 停下来等运维看差异（敏感值不显示）后确认，**确认前不改集群** |
| 白名单核对 | 按内容逐条核对（§6）；有缺的停下，白名单团队补登记后点「已补登记，重新核对」 |
| 网关滚动更新 | 应用配置与清单，网关滚动更新（前端由前端方部署，不在发版台里） |
| 池子在线替换 | 逐个槽位：等这个人不忙 → 把他的状态写回 NAS → 换镜像（每槽位约 3 秒）；管家最后换。用户下一句话自动恢复 |
| 导入环境 | 版本要求时删掉旧的知识库导入容器（NAS 上的数据不动，管理员下次进入时按新版本重建） |
| 知识库标准包 | 跑一次安装 Job（同版本跳过） |
| 冒烟验证 | 冒烟工号经网关登录、一次真实对话、一份只读诊断报告、一次知识库检索 |
| 完成 | 记下当前版本与配置版本，生成发布报告 |

**暂停**在两步之间生效。**失败**时停在那一步，日志里写着原因：处理后选「从这一步续跑」（步骤可重复执行，只补做没做完的部分），
或选「回滚」。冒烟因为模型服务方一时过载失败的，等一会儿直接续跑即可。

**回滚** = 以上一个版本为目标再走一遍：镜像已在仓库，白名单、导入环境与知识库标准包不动；资源配置用当前的，集群里现场改过的配置值照样保留。

## 6. 白名单核对

白名单由白名单团队按《部署上线方案》手工执行，发版台**只核对**：把本版本应有的每个脚本（名字、正文 md5、参数）与中间件库
`grmp.script_config` 里 `scene='AGENT'` 的登记逐条比对，分「已登记且一致 / 未登记 / 正文不一致 / 参数不一致 / 重名 / 未生效」。

- **导出文件**：请白名单团队执行界面给出的 SELECT，把结果导出为 CSV，在「资源配置 · 白名单」上传。
- **只读账号**：发版台直接连中间件库查（只读会话、30 秒语句超时）。账号只需 schema `grmp` 的 USAGE 与这张表的 SELECT。
  **GaussDB 默认的 sha256 认证标准客户端不认**：只读账号要在 `password_encryption_type` 为 0 或 1 时创建、pg_hba 对跳板机用 md5；
  做不到就用导出文件。连不上时扫描会写明是认证方式、口令、pg_hba、库名、权限还是网络。

## 7. 安全

- 不做登录，只听跳板机本机；别的机器经 ssh 转发访问。
- 状态目录权限 0700，库文件 0600；日志与界面不出现密钥值。写进集群的密钥只留指纹。
- 对集群的改动全部经过「变更预览 · 确认」；不 `apply -k`，不删命名空间、PV。网关为用户建的诊断容器不动；知识库导入容器只在版本要求时删除（NAS 上的数据不动）。
- 发版台以启动它的跳板机用户身份运行（不是 root）。

## 8. 看什么、留什么

- 「历史与回滚」：每次发布的版本、配置版本、用时、各步结果；「操作记录」：谁在什么时候改了什么（配置项名，不含敏感值）。
- 发布报告：完成页「发布报告」。
- 出问题需要我方协助时，把**状态目录**打包发来（不含密钥值）。

## 9. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 启动脚本说「没有本机架构的发版台镜像」 | 包目录里缺 `gaussdb-agent-release-*-<架构>.tar.gz`，重新拷包 |
| 扫描「Kubernetes」失败，日志里是 exec / plugin | kubeconfig 用了 exec 认证插件（如云厂商的登录程序），换成令牌或证书方式的 kubeconfig |
| 扫描「Kubernetes」标黄，说 kubectl 与集群相差几个小版本 | `release-console.sh --kubectl <集群配套的 kubectl>` 重启 |
| 发布包在列表里标红「是链接，看不到」 | 发布包目录里用了指向别处的链接；拷真文件进来 |
| 池子替换一直「等不忙」 | 有人正在等回答。等满 30 分钟交给运维：「继续等待」，或「强制转保留」（先把他的数据写回 NAS，这次回答会中断） |
| 冒烟「真实对话」失败，原文是 Service is too busy | 模型服务方过载，稍后从冒烟这一步续跑 |
