# Fuyao 沙箱手册（预览）

> 本文随本仓库标签 `agent-v1.5.1` 发布。文中提到的 `k8s/`、`docker/`、`scripts/`、`gateway/`、`e2b/` 等路径，指本仓库或离线交付包里的同名目录。

> **预览**：Fuyao 沙箱模式随 `agent-v1.5.0` 发布，属于**预览**功能。平台的三项安全前提（envd 认证、沙箱出网限制、OpenSandbox 认证）落实之前，**只用于测试环境**：只用测试账号、测试库与模拟中间件，不接生产数据库与真实的中间件令牌。按需、固定池化两种模式不受影响。

实施 / 运维：在 openFuyao 沙箱平台（OpenSandbox + Flux + E2B 微型虚拟机）上运行智能体 ——
**每位用户一台沙箱（虚拟机）**，诊断环境与知识库导入环境都是沙箱。网关 `RUNTIME_MODE=fuyao`。

与「按需」「固定池化」两种模式用同一套镜像、同一套技能与提示词；差别只在用户的运行环境由谁提供、数据怎么落盘。

## 0. 一页看懂

| | 按需 / 固定池化 | Fuyao 沙箱 |
|---|---|---|
| 用户运行环境 | 网关调 K8s 建 Pod（或从池子分槽位） | 网关调 OpenSandbox 建沙箱（微型虚拟机），每人每种环境一台 |
| 用户数据 | Pod 直接挂 NAS | 沙箱挂不了 NAS（平台不传卷）：沙箱本地盘 + **状态服务**每 60 秒回写 NAS |
| 中间件令牌 / 模型密钥 | Pod 里的凭据代理（或池子管家） | 集群里的**凭据代理服务**；沙箱里只有一个中继，密钥不进沙箱 |
| 闲置 | 回收 Pod / 转保留 | 收尾回写后**暂停**（内存快照，恢复约 3 秒），超过保留期删除（暂停前没回写成的不删，交运维） |
| 镜像 | 推内网仓库 | 另外构建成平台的**模板**（E2B template），每版本两份：诊断、导入 |

集群里新增两个服务（都用 runtime 镜像，入口不同）：

| 服务 | 端口 | 作用 |
|---|---|---|
| `statesvc` 状态服务 | 8090 | 唯一读写 NAS 的一方：沙箱启动时下发本人状态与知识库、运行中增量回写、收尾、本人目录独占；知识库发布；记录各沙箱的当前地址 |
| `credproxy` 凭据代理服务 | 8091 | 按沙箱令牌认人：中间件请求加本人令牌（与 SM2 签名），模型请求加模型密钥 |

沙箱里由启动器（`podctl fuyao-start`）以 systemd 起三个服务：`gsdb-credrelay`（中继，root）、`gsdb-statesync`
（后台同步，root）、`gsdb-agent`（opencode 与技能，`agent` 用户，无 sudo）。技能与 opencode 一行不改。

实测（鲲鹏 920 + openFuyao，2026-11-18）：新用户从没有沙箱到能对话约 5–6 秒（诊断、导入相同，两个模板都内置官方文档集）；
再次进入约 1–2 秒；暂停后回来 2.9–3.8 秒（恢复后只认沙箱向状态服务报到的地址，每 0.5 秒问一次）；每种模板注册 1–6 分钟。
空闲的沙箱实际约 0.55 GiB 内存、1.4% CPU，暂停的不占宿主机内存与 CPU。

## 1. 访问路径

```
浏览器 → SSO / Ingress → 网关（fuyao 模式）──OpenSandbox API──→ 建 / 暂停 / 恢复 / 删除沙箱
                              │
                              ├──envd 49983──→ 沙箱：下发配置、启动、收尾（只在启停时用）
                              └──4096 / 4097 / 4095──→ 沙箱：对话、报告、剪藏（转发，SSE 实时）

沙箱 ──沙箱令牌──→ statesvc（NAS）      沙箱 ──沙箱令牌──→ credproxy ──→ 中间件 / 模型服务
```

- 沙箱令牌：网关用控制密钥（Secret `sandbox-control`）签发，带沙箱 ID、工号、环境种类；两个集群服务只认令牌里的工号，
  一台沙箱拿不到别人的目录与令牌。
- 沙箱的 DNS 解析不了集群域名：网关把两个服务的地址解析成 ClusterIP 后下发。

## 2. 平台前提

### 2.1 部署前要平台提供的

| 项 | 说明 |
|---|---|
| OpenSandbox 地址 | 填 `FUYAO_API`；开了认证时 API Key 放 Secret `fuyao-api`（键 `API_KEY`） |
| 两个沙箱组 | 诊断、导入各一个（`k8s/fuyao/sandboxgroups.yaml` 是样例，容量按同时在用的人数定），由平台管理员 apply |
| 模板构建主机的 root | 模板构建服务所在主机；`scripts/build-e2b-template.py` 要在那里运行（《Fuyao沙箱部署手册》§4） |
| 网络 | 网关 Pod → 沙箱的 Pod 网段（4095 / 4096 / 4097 / 49983）；沙箱 → 两个集群服务的 ClusterIP |

### 2.2 上线前必须由平台落实的安全前提

| 前提 | 原因 |
|---|---|
| envd（49983）开启认证，或阻断沙箱之间、普通 Pod 到沙箱 envd 端口的访问 | 实测 envd 无认证，一台沙箱可以 root 身份在另一台沙箱里执行命令 |
| 宿主机侧限制沙箱出网，只放行两个集群服务（与平台需要的地址） | 平台当前不能按沙箱下发出网规则，实测虚拟机出网不受限 |
| OpenSandbox 开启认证 | 生产环境不得免认证 |

### 2.3 已知平台行为（我方已处理，无需配置）

| 平台行为（实测） | 我方处理 |
|---|---|
| 模板构建不处理 OCI whiteout：上层删掉的文件会回来，`.wh.*` 标记留在根文件系统 | 模板镜像压成一层（`docker/Dockerfile.e2b`） |
| 建沙箱带寿命时到点直接删、不能续期，寿命上限 24 小时 | 默认不设寿命（不设就没有到期时间）；设了则到期前 15 分钟收尾删除 |
| 恢复后沙箱换了地址，查询接口仍回旧地址 | 恢复过的沙箱只认它用自己的令牌、在恢复之后向状态服务报到的地址；平台给的地址一律不用（旧地址可能已是别人的沙箱，往那里探活会送出口令） |
| 单台查询不带业务 metadata、列举不回到期时间 | 一律从列举取；到期时刻建沙箱时自己记 |
| 模板构建服务拉不了公网仓库（没有根证书） | 构建时在本机起只读临时仓库（`scripts/oci-serve.py`，只听 127.0.0.1） |
| 模板参数里的磁盘大小不生效（磁盘 = 镜像大小 + 约 0.5GB） | 模板里放 6GB 全零占位文件，首次启动删除，空出约 8GB |
| 删除沙箱时虚拟机收不到信号 | 删除前由网关触发收尾回写 |
| 模板构建服务重启后第一次构建会集中补建网络槽位，期间宿主机负载很高、数分钟 | 避开业务高峰构建模板 |

## 3. 部署

**照《Fuyao沙箱部署手册》做**（部署前检查与资源测算、导入镜像、注册模板、沙箱组、Secret 与配置、现场 overlay、上线验证、
升级、扩容、卸载）。本手册不再重复部署步骤，只列要点：

- Secret：在《参数手册》③ 的基础上**必须**有 `sandbox-control`（键 `KEY`，≥16 字符，网关与两个集群服务共用）；
  `gateway-auth` 的 `ADMIN_TOKEN` **必填**（运维接口与发版台要用，1.5.0 起缺了网关拒绝启动）；`grmp-token-<工号>` 照旧每人一个。
- 沙箱组：同时运行的上限 = 承载 Pod 数 × `maxSandboxesPerPod`，**暂停的不占名额**；平台只按 `agentPodMin` 起承载 Pod，最小值设成与最大值相同；
  实际容量以子组（`kubectl -n flux-system get ssg`）为准。每台的预留可以低于上限（CPU 超分），内存不超分。
- 模板：名字由版本标签派生（`gsdb-runtime-v<主>-<次>-<修订>`、`gsdb-import-v<主>-<次>-<修订>`），在模板构建主机上用
  `build-e2b-template.py --from-oci` 注册；虚拟机规格由注册参数 `--cpu` / `--memory` 决定。
- 部署清单：以 `k8s/overlays/fuyao` 为底写现场 overlay。64K 页内核、多核节点上的两处 OOM（前端 nginx 进程数、标准知识库 Job 内存）1.5.0 起已在产品里处理，不用再打补丁。

## 4. 参数（ConfigMap `gateway-config`）

| 参数 | 默认值 | 说明 |
|---|---|---|
| `RUNTIME_MODE` | `ondemand` | 设 `fuyao` |
| `FUYAO_API` | 空 | OpenSandbox 地址，如 `http://opensandbox-server.<平台命名空间>.svc:80`；fuyao 模式必填 |
| `FUYAO_RUNTIME_TEMPLATE` / `FUYAO_IMPORT_TEMPLATE` | 空 | 两个模板名（《Fuyao沙箱部署手册》§4）；必填。发版台升级时自动改 |
| `FUYAO_RUNTIME_GROUP` / `FUYAO_IMPORT_GROUP` | 空 | 两个沙箱组；必填 |
| `FUYAO_CPU` / `FUYAO_MEMORY` | `2` / `4Gi` | 建沙箱请求里的资源字段（平台要求必填；虚拟机实际规格由模板决定，与沙箱组规格保持一致） |
| `FUYAO_SANDBOX_TIMEOUT` | `0` | 沙箱寿命（秒）。`0` = 不设（推荐）；平台强制要求时填 ≥1800、不超过平台上限 |
| `FUYAO_IDLE_SECONDS` | `1800` | 闲置多久收尾回写并暂停（≥300） |
| `FUYAO_RETAIN_DAYS` | `7` | 暂停多少天后删除（≥1） |
| `FUYAO_PAUSE` | `1` | 平台不支持暂停时设 `0`：闲置即收尾后删除 |
| `FUYAO_SWEEP_SECONDS` | `30` | 清扫周期（≥5） |
| `FUYAO_WAIT_SECONDS` | `90` | 一次请求为准备沙箱最多等多久，等不到回等待页（≥10） |
| `FUYAO_STATE_URL` / `FUYAO_CREDPROXY_URL` | 空 | 留空 = 按网关所在命名空间推导（`http://statesvc.<命名空间>.svc:8090`、`http://credproxy.<命名空间>.svc:8091`）；网关解析成 ClusterIP 再下发 |

`agent-config`（中间件、模型、实例别名、剪藏）与按需模式完全相同，由网关在启动沙箱时下发。

## 5. 生命周期

| 事件 | 动作 |
|---|---|
| 本人没有沙箱 | 建沙箱 → 下发配置与沙箱令牌 → 启动器取独占、载入本人状态与知识库 → 起三个服务 → 探活 |
| 本人沙箱已暂停 | 恢复（约 3 秒）→ 等沙箱里的同步报到（每 5 秒一次），网关据此拿到新地址 → 探活 |
| 闲置超过 `FUYAO_IDLE_SECONDS`、没有会话在跑 | 收尾回写 → 暂停（记下回写是否成功） |
| 暂停超过 `FUYAO_RETAIN_DAYS` | 暂停前已回写的删除，下次登录重建；暂停前没回写成的不删，交运维（§7.1） |
| 发版换了模板 | 旧版沙箱：在用的不打断；闲置时收尾、放开独占后删除；暂停前已回写的直接删除；下次登录按新模板建。`/admin/fuyao` 的 `outdated` 是剩余台数 |
| 设了寿命、离到期不到 15 分钟 | 收尾、放开独占后删除（有会话在跑的等到最后 5 分钟） |
| 启动器在同一台沙箱里接连失败 3 次 | 用户看到「环境准备失败，请联系管理员」，网关日志记原因；运维删除这台后重建 |
| 两个网关副本同时为一个人建了两台 | 只留最早那台 |
| 沙箱组满了 | 等待页，有空位自动进入 |

**非交互请求不建、不恢复**（探活、事件流）：开着的标签页不会把暂停的沙箱拉起来。

## 6. 数据：存什么、丢什么

- 本人状态（会话、工作区、报告、备份等，与按需模式同一套目录规则）在沙箱本地盘，后台同步每 60 秒增量回写 NAS 的
  `users/<工号>/`（导入环境 `admins/<工号>/`）；暂停与删除之前都做一次完整回写。
- 同一个人的目录同时只允许一台沙箱写（独占，30 秒续一次，90 秒没续算过期）。
- 知识库：诊断环境启动时按清单增量拉取（只读），运行中每 60 秒刷新；导入环境建完索引后发布，发布先核对版本（别人先发布了就不写），
  官方文档集随模板发版，不经状态服务下发、发布也不动它。
- 会丢的：沙箱被平台强行删除（不经网关）时，最后一次成功同步之后的改动——正常约一个同步周期（60 秒），
  同步连续失败时会更多；运维带 `force` 强制删除回写没成功的沙箱时同理。网关自己不会删这种沙箱：
  清扫器不删「暂停前没回写成」的（过了保留期也只记日志、在 `/admin/fuyao` 里计数），`delete` 不带 `force` 时回 409。

## 7. 运维

### 7.1 运维接口（头 `X-Admin-Token`，Secret `gateway-auth` 的 `ADMIN_TOKEN`）

```bash
curl -H "X-Admin-Token: $T" http://<网关>/admin/fuyao                        # 全部沙箱:工号、种类、状态、模板、是否旧版
curl -X POST -H "X-Admin-Token: $T" -d '{"sandbox": "<沙箱 ID>"}' http://<网关>/admin/fuyao/stop     # 只回写
curl -X POST ... /admin/fuyao/pause    # 回写后暂停
curl -X POST ... /admin/fuyao/resume
curl -X POST ... /admin/fuyao/delete   # 回写、放开独占后删除;下次登录重建
curl -X POST -H "X-Admin-Token: $T" -d '{"sandbox": "<沙箱 ID>", "force": true}' http://<网关>/admin/fuyao/delete   # 强制删除
```

只操作本智能体建的沙箱（metadata `gsdb-app=gaussdb-agent`）。

`delete` 只删最后的状态已在 NAS 上的沙箱：在跑的先收尾回写，成功才删；暂停的看暂停前回写成没成（`gsdb-synced=1`）。
否则回 **409**、不删，`error` 写明原因和下一步（在跑的稍后重试；暂停的先 `resume` 再 `delete`）。
确认可以丢掉最后一次成功同步之后的改动，才带 `"force": true`，回执里 `forced: true`。发版台冒烟前删冒烟工号的旧版沙箱时固定带 `force`（只有测试数据）。

摘要里每台暂停的沙箱有 `synced_before_pause`；`unsynced_over_retention` 是「暂停已过保留期、但暂停前没回写成，所以没删」的台数，
不为 0 时按上面的办法逐台处理（暂停的沙箱不占运行名额，但不处理就一直留着）。

### 7.1a 资源大盘（运维管理员，大盘「运维 · 资源大盘」）

- **谁能看**：角色头里带 `OPS_ADMIN_ROLES`（gateway-config，默认 `ops-admin`）之一，或工号登记在 ConfigMap `agent-roles` 的 `ops-admins` 里（每行一个，默认空）。别人看不到导航入口，直接访问回无权限。
- **数据**：网关自己答 `/dash/api/resources`（缓存 20 秒，页面 30 秒刷新），不建、不唤醒沙箱。每一块各自降级，读不到的块写明原因、不显示数字：
  - 沙箱、状态、模板、暂停前回写：网关清扫器（与 `/admin/fuyao` 同一份）；
  - 容量（只算同时运行的沙箱，暂停的不占）、承载 Pod、每台在哪个承载 Pod：平台的 `sandbox.flux.io`，要平台管理员 apply `k8s/fuyao/platform-read.yaml`（只读 ClusterRole，只给 sandboxgroups / subsandboxgroups / sandboxes 的 get / list；overlay 已包含）；
  - 今天各工号请求次数、24 小时趋势、NAS 用量：状态服务（网关每 30 秒报请求计数、清扫器每轮报台数；状态服务每 5 分钟算一次 NAS 用量，计数落在 NAS 的 `.ops/usage.json`）。这几个接口只认网关用控制密钥派生子密钥签的请求，沙箱令牌调不通；
  - 实际 CPU / 内存：metrics-server，没装就标「未装 metrics-server」；节点容量与 token 用量这一版不取。
- **产品名**：gateway-config 的 `PRODUCT_NAME`（默认「GaussDB 智能体」），大盘标题、logo 与日报报头都用它。

### 7.2 升级（发版台）

Fuyao 模式下发版台的步骤：模板核对（目标版本的两个模板各建一台探测沙箱，进入运行即删；模板缺了会给出注册模板的完整命令）
→ 配置迁移（自动改两个模板名）→ 网关滚动 → 沙箱换版（报告还剩几台旧版沙箱，闲置后自动换新）→ 冒烟。
没有「池子在线替换」与「删除旧的导入容器」两步。首次部署不走发版台，按《Fuyao沙箱部署手册》；
发版台不保留现场对 Deployment、Job 的补丁（1.5.0 起 64K 页节点不再需要这类补丁，部署手册 §7.3）。

### 7.3 换根规范

`rootspec-overlay.sh` 在离线包上换根规范时，包里有模板 OCI 包就一并重建；之后在模板构建主机上用新包重新注册模板（部署手册 §4），
再由发版台或手工改模板名。

## 8. 排查

| 现象 | 看哪里 / 怎么办 |
|---|---|
| 一直是「正在为您准备环境」 | 网关日志 `Fuyao:` 开头的行：模板名不存在、沙箱组满、启动器失败（附启动器最后几行输出） |
| 「环境准备失败，请联系管理员」 | 网关日志「启动器接连失败」那行；多为模板有问题。修好后 `/admin/fuyao/delete` 删除那台，下次登录重建（回 409 说明收尾回写没成功，确认可丢再带 `force`） |
| `/admin/fuyao` 的 `unsynced_over_retention` 不为 0 | 这些沙箱暂停前没回写成，清扫器过了保留期也不删（网关日志「不自动删除」那行）。按 §7.1 先 `resume` 再 `delete`，或确认可丢后带 `force` |
| 暂停后回来要等较久（正常 3–4 秒） | 网关要等沙箱里的同步向状态服务报到后才拿到新地址（平台恢复后不回新地址）；久等说明没报到，查沙箱到状态服务 8090 的网络 |
| 清扫器日志「恢复后还没报到（地址未知）」、运维动作回 409「地址未知」 | 沙箱恢复了但后台同步没报到：查沙箱里 `gsdb-statesync` 服务与到状态服务（8090）的网络。网关在报到前不会碰它；确认可丢可带 `force` 删除 |
| 建沙箱回 400「timeout exceeds configured maximum」 | `FUYAO_SANDBOX_TIMEOUT` 超过平台上限；建议设 `0` |
| 模板注册失败「x509 unknown authority」 | 构建服务拉公网仓库失败：用脚本默认方式（本机临时仓库）或 `--from-oci` |
| 实例别名不认（智能体要 IP） | 看沙箱里 `/run/gsdb/agent.env` 是否有 `GRMP_INSTANCE_ALIASES`；网关下发的是 `agent-config`，改完后对新启动的沙箱生效 |
| 状态服务 / 凭据代理服务探活超时 | 宿主机负载过高（例如模板构建服务刚重启后的第一次构建），等负载回落 |

## 9. 残余风险

- §2.2 的三项安全前提未落实前，沙箱之间、沙箱与外部之间的隔离依赖平台默认配置，不满足生产要求。
- 状态服务单副本（`Recreate`）：重启期间沙箱回写与新沙箱启动会失败重试，最长约 1 分钟；地址记录在内存里，重启后 30 秒内由各沙箱补齐。
- 沙箱本地盘约 8GB 可用：单人工作区很大时会写满，回写与对话都会失败（与按需模式 Pod 的临时盘上限同类）。
