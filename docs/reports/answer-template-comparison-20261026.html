用 leading hint 来指定 join 顺序，也就是 Join 顺序的 hint。

语法

/* 只定顺序，内外表不限 */
select /*+ leading(t1 t2 t3 t4) */ ...
from t1, t2, t3, t4
where ...;

/* 同时定顺序和内外表（仅最外层生效） */
select /*+ leading((t1 t2 t3 t4)) */ ...
from t1, t2, t3, t4
where ...;

两种写法的区别：

依据《Join顺序的Hint》(PD-G25132C-01060)：leading(t1 t2 t3 t4) 表示各表先后 join 的顺序不限内外表；leading((t1 t2 t3 t4)) 表示 t1 与 t2 先 join、t2 做内表，再依次与 t3、t4 join 且它们都做内表。

括号还可以用来控制子集的 join 顺序：

/* t2、t3、t4 先 join，再和 t1、t5 join */
select /*+ leading(t1 (t2 t3 t4) t5) */ ...

依据《Join顺序的Hint》(PD-G25132C-01060)：表列表中可用括号指定优先级，表之间用空格分隔；表须在当前层（或提升的子查询）中存在且唯一，同一张表只能出现一次；有别名时必须写别名，且不能带 schema，否则报语义错误。

官方示例

explain select /*+ leading((((((store_sales store) promotion) item) customer) ad2) store_returns)
                 leading((store store_sales)) */ ...

依据《Join顺序的Hint》(PD-G25132C-01060)：该 hint 表示 store_sales 与 store 先 join（store_sales 做内表），再依次与 promotion、item、customer、ad2、store_returns join。

  • 写完后用 explain 对照计划验证 hint 是否真的被采用；若 hint 冲突或失效，计划顶端通常会给 warning 提示。

要指定 join 顺序，可以选用 leading hint。hint 必须以注释的形式紧跟在 SELECT、INSERT、UPDATE、DELETE、MERGE 这些关键字之后；同一个查询里可以写多个 hint，hint 之间用空格分隔；关键字和 hint 之间不能夹注释，否则 hint 会失效。

指定 join 顺序的写法有两种：leading([@queryblock] join_table_list) 只固定顺序，不限定内外表；leading((join_table_list)) 在外层再套一层括号，连内外表一起固定，而且内外表的顺序只在当前层最外层生效（引用自 GaussDB 官方文档库 PD-G25132C-01060）

-- 只定顺序，不限定谁是内表
SELECT /*+ leading(t1 t2 t3) */ *
  FROM t1 JOIN t2 ON t1.id = t2.id JOIN t3 ON t2.id = t3.id;

-- 同时定顺序和内外表：t1 与 t2 先 join（t2 为内表），再与 t3 join（t3 为内表）
SELECT /*+ leading((t1 t2 t3)) */ *
  FROM t1 JOIN t2 ON t1.id = t2.id JOIN t3 ON t2.id = t3.id;

表列表中可再套括号指定优先级，如 leading(t1 (t2 t3 t4) t5) 表示 t2、t3、t4 先 join。表名规则：join_table_list 中的表必须在当前层或提升后的子查询中存在且唯一，每张表只能出现一次；表有别名时必须用别名，且不能带 schema（引用自 GaussDB 官方文档库 PD-G25132C-01060）
